# TransFactor

## 摘要
TransFactor 是一个面向代码现代化的工具，旨在自动将 C/C++ 语言代码迁移到 Rust 语言。通过结合 clang 提供的抽象语法树（AST）解析能力和大模型驱动的智能工作流，TransFactor 能够高效解决 C/C++ 代码迁移过程中复杂的语法映射、类型安全转换和内存管理等问题。
该项目帮助开发者提升代码的安全性、可维护性和现代化程度。

## 作品概述
### 背景及应用领域

TransFactor 致力于解决 C/C++ 到 Rust 代码迁移的复杂性问题，以应对操作系统、网络安全、金融科技等领域对软件安全性和可靠性的严苛需求。C/C++ 广泛应用于这些领域，其指针操作和手动内存管理提供了高灵活性，但也带来了缓冲区溢出、悬空指针等潜在隐患。Rust 凭借其内存安全与线程安全的特性，可以有效规避这些问题，特别是在金融、医疗和网络安全等对安全要求极高的场景中意义重大。本项目结合 clang AST 和大模型驱动的智能工作流，提供高效的 C/C++ 到 Rust 代码自动迁移工具，广泛适用于系统软件、嵌入式系统、网络与安全软件以及游戏开发等领域，帮助开发者提升软件的安全性、稳定性和维护效率。


### 功能描述
- **依赖分析与拓扑构建**
  - **C/C++ 项目依赖分析**：对给定 C/C++ 工程的源码进行全量扫描，利用 clang 解析构建抽象语法树（AST），提取头文件、源文件、代码节点之间的引用关系，构建完整的细粒度依赖关系图。
  - **拓扑排序和并行处理**：基于依赖图对代码文件进行拓扑排序，识别出转译过程中的先后顺序与可并行处理的模块及代码节点，为后续的代码转译、测试与性能优化提供高效的处理策略。
- **代码转译与智能协作工作流**
  - **自动代码转译**：基于大模型驱动的智能化工作流，将 C/C++ 源码自动转换为 Rust 代码。
  - **多智能体协作**：利用多智能体并行协作、共同完成代码转译、错误修复、测试用例及性能测试任务。
  - **多采样与树搜索优化**：在转译过程中采用多次采样和搜索树策略，确保在多种潜在转译方案中找到最优或最合适的 Rust 实现，从而提高生成代码的可读性、性能与安全性。
- **记忆存储与经验积累**
  - **转译过程记忆**：在持续的转译和错误修复过程中记录所采用的方法、策略和决策信息，为后续的类似问题提供快速参考与解决路径。
  - **经验积累与模式识别**：对历史转译案例进行归纳与分析，形成可复用的修复模式和最佳实践，从而不断提升转译质量与效率。
- **错误修复与持续迭代**
  - **语法与类型纠错**：针对转译过程中产生的语法不匹配、类型不一致等语法编译错误问题进行自动纠正与修补。
  - **测试用例错误修复**：对转译测试用例中出现的问题进行定向修复，保证转译后的测试代码与原始测试逻辑一致且可正确运行。
- **测试转译与质量保证**
  - **测试用例转译**：将原有的 C/C++ 测试用例对应迁移至 Rust，保证测试逻辑和场景的一致性，使转译后的代码在同等或更高标准下接受验证。
  - **测试报告生成**：在转译和运行测试用例后自动生成测试报告，详细展示转译记录、测试通过情况等信息。
- **性能测试**：基于转译后的 Rust 代码生成性能测试代码，并借助`criterion`生成性能测试报告。

- **技术栈**：

  - 向量库：ChromaDB
  - 后端：Python

- **关键技术**：[描述实现过程中遇到的关键技术挑战及其解决方案]
  - **AST 解析及依赖图构建**
    - 关键技术点：
      - 基于 clang 工具链对 C/C++ 源码进行 AST 解析，获取精确的语法和代码节点类型信息，以便转译时采用不同的规则。
      - 将 AST 中的节点及依赖信息抽取为可管理的数据结构DGNode，用于构建完整的代码依赖关系图。

    - 挑战：
      - **上下文容量限制**：直接将全量 C/C++ 源码传入大模型会大幅超出上下文限制，导致模型无法正常处理。
      - **引用关系缺失**：分批传入时，不同文件之间的引用关系（如头文件与源文件的函数调用关系、类型依赖）可能无法被模型完整地识别和处理，导致生成的代码缺乏一致性或遗漏必要的依赖信息。
      - **转译粒度难以确定**：将整个文件直接传入进行转译，粒度过大，可能导致生成代码过于笼统，且难以局部优化；但若粒度过细，模型可能无法识别分割片段的语义上下文，导致错误或不完整的代码生成。

    - 解决方案：
      - **分层提取依赖信息**：使用 clang 构建项目的 AST 时，将语法树分层提取。分别提取文件级依赖关系及代码节点级依赖关系。
      - **上下文构建**：基于代码节点级依赖关系，构建拓扑排序并合并关联代码代码，构建适合的转译单位。

  - **多智能体驱动智能工作流**
    - 关键技术点：
      - **智能体协作框架**：采用多智能体协作机制，每个智能体专注于特定的任务模块（如代码转译、错误修复、性能测试），实现并行化和高效协作。
      - **候选生成与筛选**：通过并行生成多个候选转译方案，评估候选方案的安全性、性能和代码可读性，选择最优方案作为输出。
      - **动态学习与改进**：智能体利用记忆存储系统记录转译经验和错误修复记录，形成知识库并动态更新，从而在后续转译过程中不断优化生成质量。

    - 挑战：
      - **转译质量难以保证**：不同代码采取的转译策略及风格不同，无法控制。
      - **无法有效的错误分析**：通过简单的 Prompt 难以进行有效的错误分析，如测试错误可能由测试用例本身错误、测试代码错误、被测代码错误等多种原因导致。

    - 解决方案：
      - **细粒度转译**：通过细粒度控制转译的代码节点，根据不同的代码节点类型，为其定制特殊的转译规则，进而实现风格的统一。
      - **经验学习**：正确转译的转译过程会被存储到数据库与知识库中，为后续转译提供经验指导。
      - **定制工作流**：针对错误，定制不同的修复工作流，通过多轮交互迭代，实现错误修复。


## 创新点

- **基于依赖图的高效并行转译**：利用依赖关系图对源项目进行精细分析与拓扑排序，有效识别可并行处理的模块，协同分配转译资源，在保证结果正确性的前提下明显缩短整体转译时间。
- **基于内外循环的多智能体工作流**：在内循环中，每个智能体基于既定任务细分出多个子步骤并连续迭代执行，形成单体内高效而有序的处理闭环；在外循环中，各智能体之间通过统一调度与协同策略整合各自的成果，以团队合作的形式实现整体目标。
- **渐进式转译经验积累机制**：在每次转译与修复后对经验进行提炼与沉淀，逐步形成可复用的知识结构，使系统在后续面对类似问题时能快速调用既有经验，加速转译流程并提升稳定性。

## 如何运行
### 环境准备
- **操作系统**：Windows, Linux
- **依赖项**：
    - python 3.11.10
    - python3-venv
    - llvm 14.0
    - clang 14.0
    - graphviz 0.20.3

### 安装步骤

```
# 构建 Docker 镜像
docker build -t transfactor .
# 运行 Docker 容器
docker run -d --user root --name transfactor -v "$PWD":/usr/src/c2rust -w /usr/src/c2rust transfactor tail -f /dev/null
# 进入 Docker 容器
docker exec -it transfactor bash
# 创建并激活 Python 虚拟环境
python -m venv transfactor_venv
source transfactor_venv/bin/activate
# 安装 Python 依赖
pip install -r requirements.txt
```

### 运行程序
- **启动命令**：`bash run.sh` 或 `python Tool/transfactor/main.py --source <your-c-project> --target <your-rust-project>`

> 注意：每次运行会将将转译信息保存在 states.json 文件中，以便后续继续转译。
> 若要重新转译，请删除 states.json 文件和 <your-rust-project> 目录。
